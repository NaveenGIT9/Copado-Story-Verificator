Promote only what's verified.

The gate checks every Copado User Story against its Git feature branch and lets it be promoted only when the result is clean and still current. This guide covers installing it, using it every day, and running it.

01 · Overview

How the gate works

A User Story can be marked Ready to Promote or Promote and Deploy, or added to a promotion, only when it has been verified, the result is Clean, and nothing has been committed since.

The story's journey

CommitThrough Copado or straight to Git
VerifySix checks run live in a popup
ResultClean, or Issues to fix
Ready to PromoteAllowed by the gate rules
PromotionChecked again on add

What's in the box

V

Verify popup

A Verify action on the User Story runs six checks, shows each result with its reason, and saves the verdict on the story.

7

Gate rules

Seven validation rules stop both promote boxes being checked until the story is verified, Clean, current, approved and has no pending tests.

G

Promotion guard

A story with Issues can't be added to a promotion from any screen or the API.

W

Push webhook

GitHub reports every push to a feature/US-… branch. A new commit after verification unchecks the promote boxes.

B

Release-engineer bypass

A release engineer can let one story with Issues through, with a recorded reason. Orange banners mark the story and its promotion.

+

Create Selected Metadata

Components changed in Git but missing from the story can be registered from the popup in one click.

⏻

Org-wide switch

One custom setting turns the gate off for everyone without a deploy. Verify keeps working for information.

Verdicts

Every verification ends in one of these. The promote rules run only when a box is being checked; saving other fields is never blocked.

Clean

No check failed. Warnings are allowed.

Can promote*
Issues

At least one check failed.

Blocked · a release engineer can bypass
Failed

The run broke (for example Git couldn't be cloned) or was cancelled.

Blocked · verify again
Running

A verification is in progress.

Blocked · wait
Not verified

The status is blank.

Blocked · click Verify

* While no newer commit has arrived, the pull request is approved (or the story has no commits) and Pending Tests is 0.

The six checks

Three checks read Git history through a Copado Function (no file contents). Three read Salesforce through Apex.

CheckPassWarnFail
Git · Copado Function
Unregistered commits Every commit beyond the base branch is registered in Copado, or was made outside Copado by someone who also has a Copado commit on the story and only touched registered components. Amended or rebased commits show in teal and pass. Commits outside Copado by someone with no Copado commit on the story, on registered components: "1 commit made outside Copado by <name>". A commit outside Copado changes components not registered on the story, or the story has commits but no feature/US-… branch exists.
Metadata coverage Every component changed in Git is registered with the same type and exact name. - A changed component isn't registered, so it won't deploy. It is listed under Not registered as ADD or DELETE.
External branch merge No other branch was merged in after the branch left its base. Only the base branch was merged in. An environment, promotion or other story's branch was merged in.
Salesforce · Apex
Pull request approval Pull Requests Approved is checked, or the story has no commits. No commits but a feature branch exists, or nothing to promote at all. The story has commits and the pull request isn't approved.
Pending tests Pending Tests is 0. - Tests are pending.
Parent story dependencies Every parent story (via the base branch or a Copado dependency) is in a later environment or Completed. - A parent hasn't been promoted ahead of this story. The row names it.

Salesforce Setup3 min

GitHub signs every delivery with a shared secret, and Salesforce checks the signature against this record.

  1. Generate a secret

    PowerShell
    $b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | % { $_.ToString('x2') })

03 · Developer guide

Verify, fix, promote

You need the Copado Story Verification User permission set. Your everyday loop is: commit, Verify, fix what it finds, Verify again, promote.

12 situations. Click one to open it.
D1Verify a storyEveryday▾
Do
Open the story, click Verify, then Verify in the popup.
See
Live progress, then each check with a green, amber or red mark (passed first). Show details opens the reasons; Time taken shows Copado queue time and check time separately.
Know
You can close the popup; the result still saves. Cancel stops the run and marks the story Failed ("Verification cancelled by …").

See

  • Pending tests: run the tests until they pass.

04 · Release engineer guide

Bypass, carefully

You need User and Release Engineer. On normal stories the gate treats you like a developer. Your extra tool is Bypass Verification, for a story with Issues you accept for this release.

The bypass in one line

Issues only · Ready to Promote and promotions only · until the next Clean.

It needs a reason and records who and when. It lets you, not developers, check Ready to Promote and add the story to a promotion. Promote and Deploy stays refused. It ends by itself when a verification is Clean.

Run it day to day

For admins: the off switch, updates, routine care, troubleshooting and reference.

Turn the gate off org-wide

The custom setting Story Verification Control switches the gate off for everyone, without a deploy. It is off (gate on) by default.

  1. Open it

    Setup›Custom Settings›Story Verification Control›Manage

  2. Set the organization default

    Click New (or Edit) next to Default Organization Level Value at the top, tick Disable Story Verification, save.

  3. Or from Execute Anonymous

    Use false to turn the gate back on.

    Story_Verification_Control__c c = Story_Verification_Control__c.getOrgDefaults();
c.Disable_Story_Verification__c = true;
upsert c;

Routine care

RE

Review release engineers

Check who holds Copado Story Verification Release Engineer each quarter and remove anyone who no longer releases.

⟳

Rotate the webhook secret

Generate a new one (step 3a), update the Default record, then GitHub straight after. Deliveries in between get 401.

↯

Watch webhook deliveries

GitHub, Settings, Webhooks, Recent Deliveries. Anything other than 200 means pushes aren't reaching the story.

B

Audit bypasses

A User Story report filtered on Bypass Verification shows who bypassed what, when and why.

F

Check verification failures

Many Failed stories at once usually mean Git credentials expired in Copado. Re-authenticate, then rerun setup step 2.

Troubleshooting

"Invalid template name Story_Verification_1"

Run setup step 2. If Copado named the template differently, update TEMPLATE_API_NAME in StoryVerificationService.

"You do not have access to this story"

Assign Copado Story Verification User. Release engineers need it too.

"Could not clone the repository"

Re-authenticate the Git repository in Copado, then rerun step 2. The message ends with Git's own reason.

Stuck on "Waiting for Copado to start the job"

Copado's job queue is busy. Wait, or Cancel.

No orange banner on a bypassed story

Add the component to the page this app and profile actually use (step 6c). It shows only while bypassed and Issues.

No Yes/No prompt

The banner must be on the page. The prompt appears only for the user who just checked the box.

"Only a release engineer…" for a release engineer

Assign the Release Engineer permission set, then have them log out and in.

Bypass Verification is read-only for a release engineer

They need edit access to the field (the Release Engineer set gives it) and the field on the layout.

Webhook 200 but Branch Head SHA unchanged

Only feature/US-… branches are recorded. If a Copado trigger rejects the Automated Process user, add a PlatformEventSubscriberConfig for StoryBranchPushTrigger running as a Copado-licensed user.

Boxes stay checked after a push or Issues

Another rule or trigger in the org refused the update, or the gate is off. Re-checking is still blocked.

Nothing blocks; popup says the gate is off

Untick Disable Story Verification (above).

Glossary

Base branch
The branch a feature branch was created from: an environment branch or a parent story's feature branch.
Feature branch
feature/US-…, the story's own branch.
Registered
Known to Copado: a commit with a User Story Commit record, or a component with a User Story Metadata record.
Current
No commit has reached the branch since the commit the last verification checked.
Gate rules
The 7 validation rules guarding Ready to Promote and Promote and Deploy.
Bypassed
A story with Issues on which a release engineer checked Bypass Verification with a reason.
Release engineer
A holder of the Release Engineer permission set (custom permission Bypass_Verification_Gate).
Promotion guard
The trigger that checks each story as it's added to a promotion.
